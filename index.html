rk3318-tvbox-kvm

A ~$20 Android TV box, turned into a browser-based IP-KVM, a lapdock crash-cart console, and a front panel that finally tells the time.

The web KVM UI has no authentication

The UI binds 0.0.0.0:8081 with no login, no TLS, and no access control of any kind. Anyone who can reach that port has a keyboard and mouse on whatever machine is cabled to the gadget port. The MJPEG stream on :8080 is equally open.

  • Trusted LAN or management VLAN only. Never port-forward it.
  • For remote access, put it behind something that does authenticate — a VPN, an SSH tunnel, or an authenticating reverse proxy.
  • Want a hardened, authenticated stack instead? Use PiKVM / kvmd. This project deliberately does not compete with it.

There are no credentials anywhere in this project, because there is no auth to have credentials for. Don't mistake that for safety.

How it fits together

Video and input travel completely separate paths and meet only in the browser. The UI references the MJPEG stream directly rather than proxying it, so nothing is copied through Python.

The one constraint that shapes everything

The SoC has four USB controllers and only one can be a gadget — and on a stock box it is invariably the socket that already has everything plugged into it. Move your hub to the xHCI socket first; that frees dwc2 to become the gadget port.

controllerdevice-tree nodegadget?on a stock box
dwc2usb@ff580000✔ the only candidateeverything is plugged in here
dwc3 / xHCIusb@ff600000✘ host-only as wiredusually empty
EHCIusb@ff5c0000✘usually empty
OHCIusb@ff5d0000✘usually empty

There is also a VBUS back-feed hazard: these boxes actively source 5 V onto the OTG port, so cabling it to a PC puts two supplies on one rail. The overlay disables that regulator — VBUS stays sensed, but no longer sourced. Read the hardware notes before connecting anything you care about.

Quickstart

Replace <box-ip> with your box's address.

# 1. move the USB hub to the xHCI socket -- this frees dwc2
# 2. build and install the OTG overlay
dtc -@ -I dts -O dtb -o rk3318-otg-peripheral.dtbo \
    overlays/rk3318-otg-peripheral.dts
scp rk3318-otg-peripheral.dtbo root@<box-ip>:/boot/overlay-user/

# 3. install the gadget, capture and UI, then reboot
scp bin/hid-gadget-up root@<box-ip>:/usr/local/sbin/
scp bin/hid-send bin/kvm-ui.py root@<box-ip>:/usr/local/bin/
scp systemd/*.service root@<box-ip>:/etc/systemd/system/
ssh root@<box-ip> 'systemctl enable hid-gadget kvm-stream kvm-ui && reboot'

# 4. verify, then open http://<box-ip>:8081/
ssh root@<box-ip> 'ls /sys/class/udc/ && ls -l /dev/hidg0 /dev/hidg1'

There's a CLI seam too, independent of the browser — hid-send type "hello", hid-send key ctrl+alt+delete, hid-send move 50% 50%.

Two upstream bugs found along the way

Both written up report-ready, with the exact evidence and a suggested patch.

Armbian's rk3318 front-panel overlay cannot work as shipped

rockchip-rk3318-box-led-conf2.dtbo puts an I2C slave address in an SPI child's reg (rejected as cs36 >= max 1) and uses a compatible no driver matches. Either alone is fatal. Identical across at least rockchip64-6.12 → 7.2, so every box selecting it has a dead panel — silently. Full report →

tm16xx's out-of-tree build breaks on unpatched kernels

It ships the full mainline auxdisplay Makefile, so an M= build demands sources it lacks; and it passes its -D flags via EXTRA_CFLAGS, which modern kbuild ignores. The second is nasty because it's split-brain rather than clean — the config reaches make but not the compiler, so you get a redefinition error that reads like a source bug. Full report →

What's actually verified

Honest accounting, because "it works" in DIY hardware writeups is usually softer than it looks.

Verified on real hardware, across reboots

  • Gadget enumerates — /dev/hidg0 + hidg1 present, presenting as a composite keyboard + absolute pointer.
  • ustreamer serving MJPEG, surviving the USB renumbering the overlay causes.
  • UI: page, WebSocket handshake, every event type, malformed input, and the no-host path.
  • DisplayLink console with a visible cursor — confirmed by the compositor's own log line and an A/B on cursor-plane commits (30+ → 0).
  • Front panel: 4-digit clock tracking wall time, 5 LEDs with triggers.

Not verified / known gaps

  • Typing into a real target PC. Everything gadget-side was tested headless; whether keystrokes land, and where the absolute pointer lands at your target's resolution, needs a cabled machine.
  • No authentication, no TLS. No audio, mass-storage emulation, or ATX power control — all of which PiKVM has and this does not.
  • One box, one Armbian build. RK3318 boxes vary wildly, especially the front panel — Armbian ships seven different LED configurations.
